# 霞光 Skyglow · 火烧云概率预报（发布版）

> 本目录为**脱敏发布版**：不含任何 API Key、令牌、私钥或账户标识。
> 若需启用可选的数据源，请复制 `config.example.json` 为 `config.local.json` 后填写你自己的凭据。

一款可本地运行的朝霞/晚霞（火烧云）定量预报网页产品。基于免费的 ERA5 再分析、CAMS 大气组分与 Open-Meteo 预报接口，计算太阳—云层几何、大气光谱消光与光路上游云遮挡，输出 0–100% 的出现概率、六档强度、最佳观赏窗口与预计色彩，并提供**全国晚霞地图**与**城市精细地图**。

支持三种选点方式，位置精度保留到小数点后 4 位（约 10 m 量级），预报本身受 0.25° 模式网格限制：

1. **中文地名** — 输入「上海」「北京市海淀区」「上海 浦东」均可，按行政区后缀从最具体一段开始解析，中文输入优先返回国内同名地
2. **自定义经纬度** — 点「自定义经纬度」展开面板，分别填纬度、经度（可负），可加备注名，回车填入
3. **浏览器定位 / 地图点选** — 定位按钮取设备坐标；点地图任意格点也会回填该面板

**取数只发生在点击「开始预测」时**（或在地名框回车提交）。改地点、改日期、切换朝霞/晚霞、改直连/校验源设置都只更新参数，不发请求；此时按钮会加亮并显示 `开始预测 ●`，提示确认后再取数。这样避免"地点还没选完就先查一次"造成的额度浪费。

核心功能仅依赖 Python 标准库；可选增强项才需要额外的包（见下）。

## 运行

```bash
# Windows
setup.bat          # 首次运行：建 .venv 并装解码器
run.bat            # 启动（会自动使用 .venv）

# macOS / Linux
./setup.sh
./run.sh
```

> **打开网页报「网页似乎有问题」**：请用启动横幅里打印的地址，形如 `http://127.0.0.1:8770`。
> `0.0.0.0` 是监听地址（表示"所有网卡"），不是可访问地址，浏览器会直接拒绝；
> 端口默认 **8770**，注意别打成 8870。

> **如果运行 bat 时出现 `'art' 不是内部或外部命令` 之类的碎片报错**：说明文件被编辑器保存成了 LF 换行，cmd.exe 无法正确解析。用 `git config core.autocrlf true` 或编辑器把换行符改回 CRLF 即可；本次发布的 `setup.bat` / `run.bat` 已确保是 CRLF。

直接 `python server.py 8770` 也能跑，但**官方档案直连（ECMWF / GFS / ICON）需要 eccodes**，用系统 Python 通常没有，界面会显示「缺 eccodes」。`setup.bat` / `setup.sh` 会在本目录建 `.venv` 并装好 `requirements.txt`，`run.bat` / `run.sh` 优先使用它。

要求 Python 3.9+。开箱即用：Open-Meteo / ERA5 / CAMS 全部免费无需密钥，预测主链路不依赖任何密钥。

**本项目不内置任何 API 密钥。** WeatherAPI 与和风天气都是可选项，需自行申请后在面板或 `config.local.json` 填写；未配置时预测照常工作，只是少了校验与缺测补位。

首次查询会向 Open-Meteo 请求 25 个格点 × 3 天的逐时数据，约 2–4 秒，之后走本地缓存。

## 预测逻辑

1. **太阳几何**：NOAA 算法求日出日落、方位角与高度角（误差约 0.02°）。云底进入地球阴影的受光极限为 `α_min = −√(2h/R)`；9 km 卷云约 −3.0°，1.5 km 低云约 −1.2°。
2. **光路与光谱**：低太阳高度下光线沿地球切线传播，切点高度 `h_t = h − Rα²/2`。沿路径积分瑞利散射（τ₅₅₀=0.098，λ⁻⁴·¹）与气溶胶米散射（AOD，Ångström≈1.3），得到 400–700 nm 透射谱，经 CIE 1931 配色函数转 sRGB，直接给出预计颜色与相对亮度。
3. **云幕**：高云/中云云量决定可染色面积（饱和型响应），低云主要作为遮挡；云底高度由边界层高度（低云）与气候值（中 5.2 km / 高 8.6 km）估计。
4. **光路上游**：沿太阳方位在 120/250/380 km 三个环带取 24 点，按方位角余弦平方与距离指数加权，得到上游低云遮挡与中云消光。
5. **通透度**：AOD、相对湿度、能见度（历史缺测时由 AOD+RH 反演）与降水共同决定颜色纯度。
6. **标定层**：上述物理量取 logit 后进入岭回归（α=1.2），输出强度潜变量；再用一维 logistic 标定为概率，按标签累计频率确定六档阈值。标定参数见 `data/model.json`。

## 地图

- **两张地图都默认不生成**，各自有「生成」按钮，点开后才会请求格点数据。
- **全国晚霞图**：2.0° 规则网格（32×19 = 608 点），覆盖 73.5–135°E / 18–54°N；每个格点按当地日落时刻插值三层云量、湿度、降水、边界层高度与 AOD，再用同一模型算概率。首次生成约 25–40 秒，按（日期, 时序）缓存 6 小时。
- **城市精细图**：以所选坐标为中心、±1.5° 范围、0.25° 网格（13×13 = 169 点），与模式网格分辨率一致。未生成全国图时，城市网格自身兼顾上游采样（1.5°≈170 km 已覆盖主要光路）。叠加省界、经纬网、25/50/100 km 距离环与比例尺。
- **上游采样**：地图用格点自身做近似——沿太阳方位 ±30° 三条射线、140/280/420 km 三档距离、双线性插值；单点预报仍用 24 点环带采样。两者物理一致，地图为性能做了降采样。
- **交互**：悬停显示概率/等级/经纬度；点击地图任意格点切换到该坐标，再点「开始预测」重算；颜色为固定绝对色阶（紫→橙→金），跨日期可比。
- **配额策略（重要）**：日常查询**只取目标地点**——`/api/predict` 的 25 点环带（中心 + 120/250/380 km × 8 方位），不触发任何地图请求。全国图（608 点）与城市图（169 点）仅由各自按钮按需构建，按「日期 + 时序」或「日期 + 坐标」缓存；切换数据源只重绘、不发请求；日期或位置变更后按钮回到「生成」，需重新点击。
- **刷新策略**：同一日期内切换地点时，全国场已缓存，前端直接重绘并只请求新坐标的 0.25° 城市格点，不重复抓取全国数据。
- **边界**：阿里云 DataV.GeoAtlas 省级边界，含台湾省、香港、澳门及南海诸岛，主图右下附南海诸岛插图；未使用任何境外瓦片服务。
- **配额提醒**：全国图一次约消耗 1050 个格点请求，Open-Meteo 免费额度按调用量计。频繁切换日期可能触发 429，代码已内置指数退避与分块节流；生产部署建议自建缓存或用付费套餐。

## 四数据源并列

页面所有指标同时给出四个数据源的计算值，互不替代：

| id | 名称 | 说明 |
|---|---|---|
| `openmeteo` | Open-Meteo | best_match 多模式融合 |
| `ecmwf` | ECMWF IFS | 0.25°，`ecmwf_ifs025` |
| `gfs` | GFS | NOAA GFS seamless |
| `icon` | ICON | DWD ICON global seamless |

- 一次 HTTP 请求取回四个模式（变量带 `_ecmwf_ifs025` / `_gfs_seamless` / `_icon_seamless` 后缀），因此四源对照不增加地点配额消耗。
- 顶部四个芯片、成霞因子矩阵（行=因子，列=源）逐格显示各自数值；「分时演变」「几何模型」「晚霞地图」各有独立的数据源切换器；「晚霞方位雷达」用四种颜色在同一张图上叠加四条闭合曲线。
- 某源在该日期无数据时（典型：ERA5 存档不含 ECMWF IFS），该源所有位置统一显示 **数据获取失败**，不静默替换为其它模式。
- 气溶胶（CAMS AOD）四源共用——免费数据里没有分模式的气溶胶产品，这一点在页面中注明。

## 数据源优先级

一次查询的实际取数顺序：

概率计算（主链路）：

1. **本地缓存**（`data/predict/`）——命中即返回，不联网。
2. **Open-Meteo 官方**（api / archive / air-quality）——转发的正是 ECMWF / GFS / ICON 四家模式场。
3. **官方档案直连**（ECMWF IFS / GFS / ICON）——仅当上一层拿不到该源数据时，按开关逐个尝试。

校验与补位（旁路，按此优先级，命中即止）：

1. **WeatherAPI**（内置密钥，默认启用）
2. **和风天气**（可选，需自行配置）

> **不提供"中转/镜像"设置**：Open-Meteo 的免费额度按来源 IP 统计，指向 `api.open-meteo.com` 的任何"中转"都仍是同一台主机、同一份配额，不存在可绕开的独立额度。把第三方文档站（如 `api.aa1.cn`）当作接口地址也不行——该站只是收录文档，`/api/openmeteo` 实测返回「接口不存在」。若将来自建 Open-Meteo 实例，那是另一台服务器、独立配额，届时代码里替换 `meteo.FORECAST/ARCHIVE/AIR` 三个常量即可。



## 辅助校验源

两个外部源都**不参与概率打分**——它们只有总云量，没有低/中/高分层云量，硬拆等于编造模型最依赖的输入。它们的职责是校验与补位：

| 源 | 优先级 | 提供字段 | 用途 |
|---|---|---|---|
| **WeatherAPI** | 主 | 总云量、能见度、湿度、降水、降水概率、露点、天气现象、阵风 | ①交叉校验 ②缺测补位 ③风险提示 |
| 和风天气 | 备（仅当主源不可用） | 总云量、能见度、湿度、降水、露点 | 同上，作为冗余 |

**一次请求覆盖两个事件**：WeatherAPI 的 `forecast.json?days=3` 返回 3 天逐时数据，日出与日落共用同一次调用（按日缓存，TTL 30 分钟）。

**补位只补模型真正读取的量**，即 `vis`（决定颜色纯度）、`rh`（决定霾）、`precip`（决定冲刷）。补位来源记录在 `aux_from` 字段，例如：

```json
"aux_from": {"vis": "weatherapi", "precip": "weatherapi"}
```

**校验**结果写入 `aux_check`，并把明显分歧转成风险提示：

```json
{"cloud_ours": 63, "cloud_aux": 100, "cloud_gap": 37,
 "vis_ours_km": 12.8, "vis_aux_km": 10.0, "rh_ours": 69, "rh_aux": 76,
 "rain_chance": 26, "condition": "附近局部降雨"}
```

总云量相差 ≥35pp 或降水概率 ≥60% 时，自动追加一条风险说明。

配额护栏：WeatherAPI 默认每日上限 2000 次（免费额度 100 万次/月，远高于实际用量）；和风天气默认 800 次。

## 和风天气（校验用，非概率源）

实测确认其能力边界：

| 需要的数据 | 和风天气 | 结论 |
|---|---|---|
| 分层云量（低/中/高） | ❌ 只有 `cloudCover` 总云量（0–1） | 物理模型的核心输入缺失 |
| 气溶胶光学厚度 | ❌ 无 | AOD 仍需 CAMS |
| 能见度 | ✅ `/weather/v1/hourly`，米 | 可替代 AOD+RH 反演 |
| 湿度、露点、降水、气压 | ✅ | 可对照 |
| 太阳辐射（GHI/DNI/DHI） | ✅ 但 **0.3 元/次** | 未接入 |

**因此不做第五个概率源**：把总云量拆成三层等于凭空编造模型最依赖的量。它承担两件事：

1. **交叉校验**——交叉比对卡片末尾显示「和风天气（校验）：总云量 92%，能见度 10.1 km」，与四源诊断的总云量最大值并列。
2. **能见度补位**——ERA5 无能见度时，本应退化为 AOD+RH 反演；若和风可用，则改用真实预报值，并在该源上标记 `vis_from: qweather`。

**配额保护**（三层）：

- 每次查询最多 1 次调用（取日落最近的小时步，48 小时窗口），并缓存 1 小时。
- 每日硬上限 `daily_cap`（默认 800 次），超限即停，次日自动恢复。
- 免费额度每月 5 万次（天气与基础服务），本产品正常使用约 24 次/天/地点，日上限也不会触到。

鉴权支持两种：`X-QW-Api-Key`（简单，2027 起限制每日次数）或 JWT EdDSA（需私钥 + kid/iss/sub）。页面「和风天气」面板填写 Host、Key、日上限即可，密钥只写入本地 `config.local.json`。

## 直连模式（官方档案）

`core/direct.py` 直接访问三家官方档案，作为 Open-Meteo 转发失败时的备援，也可由用户手动开启。

| 源 | 端点 | 取数方式 | 单点耗时（本机实测） |
|---|---|---|---|
| GFS | `nomads.ncep.noaa.gov` | `.idx` 定位 LCDC/MCDC/HCDC 偏移，字节区间取 3 条 GRIB2 | ≈ 90 s（1.8 MB） |
| ECMWF IFS | `data.ecmwf.int` / S3 镜像 | `.index` 取 tcc + 850/500/300 hPa RH 的 offset/length，分条 Range | ≈ 4 s（4 × 0.6 MB，命中缓存后 0 s） |
| ICON | `opendata.dwd.de` | CLCL/CLCM/CLCH 三个 bz2，全球二十面体网格，最近邻取值 | 当前网络 7 KB/s，单变量超 3 分钟，默认关闭 |

**开关**（页面「数据源直连」面板，或 `GET/POST /api/direct`）：

- `auto`：失败时是否自动改走直连（总开关）
- `sources.ecmwf / gfs / icon`：逐源允许直连
- 配置写入 `config.local.json` 的 `direct` 段，即时生效

**降级语义**（诚实标注，不掩盖）：

- 直连只取**最近格点**，没有 24 点上游环带 → 影响"光路遮挡"因子，卡片上标注"仅取最近格点，无上游环带"。
- 直连无湿度/降水/边界层 → 用中性值，置信度上限 0.74（转发路径 0.86–0.90）。
- **ECMWF 官方 0p25 不发布分层云量**（只有总云量 `tcc`）。直连值因此由 `tcc` + 850/500/300 hPa 相对湿度按 Sundqvist 型诊断，UI 标注"由总云量与湿度廓线诊断，非模式自带分层云量"。
- 历史日期（> 2 天）不提供直连：官方档案只保留近期实时场，此时显示"数据获取失败（历史日期无官方实时档案）"。

**依赖**：`eccodes`（GRIB2 解码）+ `numpy`（ICON 网格）。缺任一则对应开关显示"缺解码器"，其余功能不受影响。运行需使用已安装这两个包的解释器：

```bash
python -m pip install eccodes numpy
python server.py 8770
```

## 官方数据源直连的可行性

`python tools/check_direct.py` 会实测三家官方档案（无需密钥）。本机实测结果：

| 源 | 端点 | 结果 |
|---|---|---|
| NOAA GFS | `nomads.ncep.noaa.gov` `.idx` + 字节区间 | ✅ 200；LCDC/MCDC/HCDC 偏移如 431166631；取回 2.2 MB GRIB2，eccodes 解出 `shortName=lcc`，网格 1440×721（0.25°） |
| ECMWF IFS | `data.ecmwf.int/forecasts/...` | ⚠️ 429（该网络被限流）；S3 镜像 `ecmwf-forecasts.s3.eu-central-1.amazonaws.com` 返回 206，可用 |
| DWD ICON | `opendata.dwd.de/.../clcl/...CLCL.grib2.bz2` | ✅ 200，4.55 MB；`gridType=unstructured_grid`，2 949 120 点（二十面体网格） |

结论：三家都免费、无需密钥，但都是 GRIB2 文件而非 JSON 接口。GFS 最容易（字节区间 + 规则经纬网格）；ECMWF 次之（每步一个整场文件，主站被限流需走 S3）；ICON 最难（全球为二十面体非结构网格，单点取值需最近邻插值）。产品因此仍以 Open-Meteo 作为传输层——它转发的正是这三家的模式场，四源对照在数值上等价于直连，工程量低一到两个数量级。

## 免费额度

Open-Meteo 的免费额度按 **「格点数 × 变量数 × 天数」加权**统计，不是按请求次数。据此只做了一处收紧：

**只取模型真正读取的 7 个变量**（三层云量、能见度、湿度、降水、边界层高度）。露点、风速风向、降水概率既不参与打分也不显示，取回来纯属浪费额度 → 变量数 11 → 7，成本降 36%。

### 为什么没有进一步削减格点

曾试验过两项更激进的省额度方案，实测后放弃：

| 方案 | 中位偏差 | p90 | 最差 | 强度等级一致率 |
|---|---|---|---|---|
| 仅中心点（省 96%） | 1.59pp | 10.1pp | **42.3pp** | 90.5% |
| 内环 9 点（省 64%） | 0.37pp | 4.0pp | 21.8pp | 94.9% |
| 中心 + 太阳侧 ±45°（7 点） | 0.29pp | 3.5pp | 12.7pp | 95.6% |
| **完整 25 点（现行）** | — | — | — | — |

基于 39 份真实 25 格点响应、1056 个（事件 × 数据源）组合测得，可用 `tools/measure_accuracy.py` 复现。

最差场景是**太阳方向上游低云 83%、而中心点 0%**：地平线遮挡因子从 0.24 跳到 1.00，概率 14% → 57%。这正是「地平线有没有云挡光」这一物理机制本身，砍掉环带等于放弃判断它。

因此上游环带**不做任何裁剪**，七日趋势同样使用完整 25 点。

### 额度不够时

如实报错（`relay_error` 回传具体原因），并退回官方档案直连（ECMWF / GFS，取最近格点、无环带）。直连结果带 `degraded` 字段标注，前端在四源 chip 的 tooltip 中说明。

## 本地缓存（默认优先）

三层缓存，查询时按顺序命中，命中即返回，不触碰网络：

| 层 | 位置 | 内容 | 过期 |
|---|---|---|---|
| 1 | `data/predict/` | 组装完成的预测、七日趋势、方位雷达 | 见下表 |
| 2 | `data/cache/` | 原始 HTTP 响应（按 URL 哈希） | 预报 1 h / 再分析 24 h / 空气 1 h |
| 3 | `data/direct/` | 解码后的 GRIB 单点 | 30 min |

第 1 层的过期策略按「资料还能变多少」定：

| 日期 | 有效期 |
|---|---|
| 昨天及更早 | 永久（再分析已定稿） |
| 今天 | 60 分钟 |
| 明天 | 3 小时 |
| 后天及以后 | 6 小时 |

- 页面左上角显示「本地缓存 · N 分钟前，有效 60 分钟」，右侧「刷新」按钮强制跳过第 1 层重新取数（`refresh=1`）。
- 切换直连开关、切换日期地点时才可能触发取数；切换数据源只重绘。
- `GET /api/cache` 查看条数与体积，`GET /api/cache?clear=1[&kind=predict]` 清空。

## 配额熔断

Open-Meteo 免费额度按地点数计，超额后同一小时内的每个请求都会失败。若仍按 8/16/24 秒退避重试，单次查询要等约 90 秒。因此加了熔断：一旦收到 429 或配额提示，标记转发通道不可用 10 分钟，后续请求**立即**失败并转走官方直连。

实测：今日查询从 88 秒降到 2.7 秒；第二次查询（命中本地缓存）0.35 秒。

## 交叉分析与可视化

- **方位雷达**：以观测点为中心，16 方位 × 6 距离（60–420 km）采样，按「可照云幕 × 低云遮挡 × 太阳方位扇区」给出 0–100 分，并在太阳方位（±90°）上单独做 13 点剖面，用于几何图与云量剖面。
- **几何模型**：由受光极限 `α_min = −√(2h/R)`、霞光深入距离 `D_glow = 2√(2Rh)`（与教程表一致：2 km→319 km、8 km→638 km）与云边界距离绘制剖面示意；时间窗来自逐分钟模型曲线。
- **四源一致性**：同一时刻四个数据源各算一次，给出极差与"一致/基本一致/分歧较大"的判定。
- **神经网络**：MLP 15–8–4–1，输入为 8 个原始气象量与 7 个物理子评分，标签为 sunsetbot 再分析「是否成霞」；与物理模型、模式集合并列展示并给出分歧程度。时间切分测试 AUC 0.794、Brier 0.174；训练集 AUC 0.881，存在过拟合，故只作为交叉参考。
- **WeatherAPI**：密钥保存在 `config.local.json`（已 gitignore，可用环境变量 `SKYGLOW_WEATHERAPI_KEY` 覆盖），仅用于总云量/能见度的一致性校验。

## 训练数据覆盖情况

审计结论：**上游全部可得记录，100% 进入了建表、标定与神经网络训练**，无抽样、无丢弃。

| 环节 | 数量 | 说明 |
|---|---|---|
| 上游站点覆盖范围 | 2022-06-24 ～ 2023-12-30 | 该范围之外实测返回 0 条 |
| 日历天数 | 555 天 | 理论上限 555 × 2 = 1110 条（日出 + 日落） |
| 实有记录 | **1109 条** | 唯一缺口：`2022-08-27 日落`，上游本身没有这条观测 |
| 重复记录 | 0 | 按 (日期, 事件) 唯一 |
| 建成特征表 | **1109 条** | `build_dataset.py` 未丢弃任何一条 |
| 物理模型标定 | **1109 条** | 部署参数 `fit_layer(all)` 用全量；时间切分仅用于报告指标（train 743 / test 366） |
| 五折交叉验证 | **1109 条** | 每折 221–222 条，各覆盖 111 天 |
| 神经网络训练 | **1109 条** | 15 维输入，无 NaN / inf；阳性 188 条、阴性 921 条 |

### 必须说明的两点局限

1. **两个模型共用同一批标签**。物理模型（岭回归 + logistic）与神经网络都在这 1109 条上拟合，因此两者的"交叉比对"**不是独立验证**，只能反映"两种函数形式在同一数据上的分歧"。真正独立的检验只有时间切分（2023 下半年）与跨气候区迁移。
2. **部署模型包含测试期样本**。报告的 AUC 0.797 / Brier 0.167 来自只在训练期拟合的模型；而线上部署的 `model.json` / `nn_model.json` 用的是全量 1109 条，对 2023-07 至 2023-12 的日期属于样本内预测，指标会偏乐观。对 2024 年之后（真正外推）不存在这个问题。

## 验证结果

时间切分：训练 2022-06-24–2023-06-30（743 条），测试 2023-07-01–2023-12-30（366 条）。
部署模型另做按日期分组的五折交叉验证（1109 条）。

| 指标 | 五折交叉验证 | 时间切分测试 | sunsetbot 同期预报 |
|---|---|---|---|
| AUC | 0.802 | 0.797 | 0.761 |
| 等级命中 ±1 档 | 81.6% | 79.0% | 84.4% |
| 完全命中 | 76.1% | 74.3% | 76.5% |
| Brier | 0.118 | 0.167 | 0.148 |
| TSS（最优阈值） | 0.244 | 0.226 | 0.523 |

要点：

- **排序能力略优于参考模型**（AUC 0.80 vs 0.76），但**概率标定在秋季偏保守**：测试期基率 24.3%，训练期 13.3%，模型给出的均值仅 12.6%，因此 Brier 偏高、高等级召回不足。这是分布漂移，不是阈值问题。
- **强度分级是弱项**。六档标签中 83% 为"基本不烧"，可用于区分强度的样本仅 188 条；模型对"是否成霞"的判别明显好于"烧到什么程度"。等级的 ±1 命中率 82%，但完全命中主要来自多数类。
- 参考模型的 TSS 更高，但其"预测质量"列可能经过人工订正，且六档离散评分会使 AUC 被低估；两组数字不宜直接排名。

```bash
python tools/fetch_reanalysis.py   # 抓标签（约 1 分钟）
python tools/fetch_grid.py         # 下载 25 格点历史场（约 15 分钟）
python tools/build_dataset.py

```

## 已知局限

- 0.25° 网格会平滑掉云缝与云边界，"云洞漏光"无法解析。
- 无云的光学厚度，厚卷层云与薄卷云被同等对待。
- 气溶胶垂直廓线未知，等效消光高度有 ±1 km 量级不确定性。
- 标签来自上海单点人工观测，存在主观差异与漏记；跨气候区使用需重新标定阈值。
- 历史日期使用 ERA5 再分析，属事后最优估计，精度高于当时的业务预报；未来日期使用业务预报，误差更大。
- 15 天以外不提供预报。

## 配额说明（重要）

Open-Meteo 免费额度按「格点数 × 变量数 × 天数」加权，不是按请求次数。单文件版没有服务端缓存兜底，一次完整加载的实际成本如下：

| 请求 | 规模 | 单位 |
|---|---|---|
| 主查询（今日为基准） | 25 格点 × 7 变量 × 3 天 | 525 |
| 七日趋势 | 25 格点 × 7 变量 × 8 天 | 1400 |
| 方位雷达 | 77 格点 × 4 变量 × 1 天 | 308 |
| 气溶胶 AOD（随主查询） | 25 格点 × 1 变量 × 3 天 | 75 |
| 气溶胶 AOD（随七日） | 25 格点 × 1 变量 × 8 天 | 200 |
| **合计** | | **约 2508** |

七日条共 8 天（今天 + 未来 7 天），窗口就是这 8 天，不多取前一天——七日条只算事件瞬时、不画时间曲线，前一天的数据不会被读取。

**七日趋势与主查询使用同一套 25 点环带**，不做降采样。原因是地平线遮挡因子取决于太阳方向上游的低云：若只取中心点，最差情形（上游低云 83% 而中心晴）的概率偏差可达 42pp，强度等级也会跳档。实测依据见 `skyglow/README.md` 的「免费额度」章节，`tools/measure_accuracy.py` 可复现。

变量已从 11 项精简到 7 项（去掉露点、风速、风向、降水概率——模型从未读取）。这是唯一一处不影响精度的削减。

合计仍属偏重。同一 IP 频繁换地点查询会触发 429，界面会自动重试（4s / 8s 退避）。作者调试时用 25 格点 × 11 变量 × 9 天的请求反复触发，直接打满了当日额度——普通使用不会这么快。

## 密钥处理

页面**不内置任何密钥**。WeatherAPI 是可选项：自己注册后填在页面底部，只写入本机 `localStorage`，不上传任何服务器。清空浏览器数据即失效。
